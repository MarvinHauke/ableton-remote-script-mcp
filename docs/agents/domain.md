# Domain Docs

How the engineering skills use this repo's domain documentation. Single context.

## Before exploring, read these

- **`docs/feature-plans/GLOSSARY.md`:** the shared language, with the terms to use and the terms
  to avoid.
- **The numbered plans** that touch the area (`docs/feature-plans/NNNN-*.md`), found through
  `docs/feature-plans/README.md`. They are the decision records; decisions live in their
  "Decisions" sections.

## Use the glossary's vocabulary

Name domain concepts with the glossary's term. A missing term is a gap: note it for
`domain-modeling`, which adds it to `docs/feature-plans/GLOSSARY.md`.

## Flag plan conflicts

When your output contradicts a plan's decision, say so openly:

> _Contradicts 0001 decision 3, but worth reopening because…_
